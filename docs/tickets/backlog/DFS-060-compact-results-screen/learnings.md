# DFS-060 learnings

- **design / architect**: a stub reached from a routed component's constructor (here `readDensity` in a field initializer of `ResultScreen`) does not fail `app.routes.spec.ts` with the stub's error. The router swallows the error during navigation, and the test times out or leaves a request open. The archetype's checklist item 3 covers specs that render the component directly. It could add that a lazily routed component's constructor stubs show up in the routes spec as a timeout, so that spec goes under Expected breakage, or the stub moves to a template-evaluated method.
- **design / architect**: the ticket's Context named only DFS-053's AC-3 and AC-5 browser flows as affected. Decision 5 (the copy button copies the full path) also changes DFS-053.AC-7, the flow at line 209 (Overlaps selected), the `.selected-label` count and the folder helper's `name + " ·"` filter. Refinement could grep `BrowserFlowTest` for every selector and text the decisions replace, as the architect does for the Vitest specs (DFS-057.L-1).
- **test / test-author**: the ticket's AC-7 scenarios assume a 36-character budget, but the screen has one fixed `PATH_BUDGET = 62`, so the budget-36 examples can only be tested on `displayPath` itself; screen-level specs need longer paths. Refinement could say which level a scenario's budget belongs to.
- **test / test-author**: `app.routes.spec.ts` (two DFS-049.AC-1 tests) fails against the stubs with a timeout and a TestBed error, not the stub's message, as design.md predicted; the red gate must accept it as expected breakage because it is not a DFS-060 test.
- **test / test-author**: `expect(() => stub()).not.toThrow()` turns the stub's `not implemented` error into an AssertionError and fails the red gate. A "never throws" scenario has to call the function bare and assert on an observable afterwards. The component archetype's `test-guide.md` could say so.
- **test / test-author**: AC-9's "open again" cannot be a second navigation to the same URL in `RouterTestingHarness` (a same-URL navigation is ignored); it is tested as a pre-filled fake storage instead.
