# DFS-059 learnings

- **design / touches gap**: adding a required field to an API record that the frontend's shared Vitest builders build as object literals (`server/frontend/src/app/results/result-test-data.ts`: `folder()`, `setPage()`) breaks `ng build`, not only `npmTest`. The production build type-checks that file too, and `:server:test` runs `ngBuild`, so no server test can run. Refinement listed `openapi.json` but not the builders. Proposal for the endpoint archetype / `/tickets refine`: when a ticket adds a required component to an existing record, grep `server/frontend/src` for the record's type name and add every file that builds it as a literal (usually `*-test-data.ts`) to `touches`.
- **design / expected-breakage run**: with `ngBuild` broken, the run had to use `-x ngBuild`. That empties `static/` and makes four frontend-serving test classes fail for a reason unrelated to the stubs. Worth noting in `archetype.md` step "Expected breakage run" as a known artifact, if `-x ngBuild` is ever used deliberately.
- **verify / scenario wording vs test helper**: the AC-4 scenario says "a RUNNING scan", but the test (rightly) uses the existing `HoldingExecutorConfiguration`, which holds the scan QUEUED. Refinement could write "a scan not yet completed" for `409 SCAN_NOT_COMPLETED` scenarios, so the scenario matches the helper every result-API test uses.
- **verify / pre-existing CLAUDE.md duplicate**: the `server` entry repeats "registry's listener folds the core's `ScanEvent`s into counts and never blocks the scanning thread." twice (from an earlier ticket). Not this ticket's to fix; worth a one-line cleanup by whichever ticket next edits that entry.
