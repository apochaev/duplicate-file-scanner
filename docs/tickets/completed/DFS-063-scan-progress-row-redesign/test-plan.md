## Fixtures and fakes

- HTTP: `provideHttpClient()`, `provideHttpClientTesting()`; `http.verify()` after each test (`ScanScreen` answers `GET /api/scans`, `ScanRow` makes no request except Cancel).
- Stub surfacing: `provideStubSurfacing()` in the providers and `await settle(fixture)` after each step (`src/testing/stub-surfacing.ts`); `scan-screen.spec.ts` keeps its local `settle()` as a one-line wrapper over the shared one.
- Fakes behind tokens: `FakeEventSource` through `EVENT_SOURCE` (a stream the test drives; it delivers exactly the progress it is given), and a fake clock through `CLOCK` (`now` in milliseconds, set before each update; no test waits on real time).
- Data builders: `scan-test-data.ts` (new, no Vitest globals): `gb()`, `scanIn(phase, update)`, `hashingHalf()`, `completed()`, `startedPhases()`, `allPhasesDone()`, `totals()`, with the canvas's numbers (38886 files, 902.9 GB, 4120 folders; 29594 compared; 13845 files, 17.1 GB; 3104 and 2987 groups); plus `progress()` and `scanEntry()` from `results/result-test-data.ts`.

## Notes for the implementer

- The 0-of-0 "finishing" case is deliberately not pinned (design.md open note 2); tests that start a hashing phase use a nonzero `hashBytesTotal`, except the AC-3 phase-change test, which only reads the overall percentage.
- Template classes the specs read: `.scan-section[data-phase]` with `section-<state>`, `.section-tag`, `.section-line1`, `.section-line2`; `.scan-overall-value`, `.scan-overall-caption`, `.scan-step`, `.scan-time-left`, `.scan-cancelling`, `.scan-failure`, `.scan-collapsed`, `.scan-expanded`, `.scan-started`, `.scan-totals`, `.scan-duration`, `.scan-finished`, `.scan-strip-thin`, `a.open-results`. A section's text is `.section-line1` / `.section-line2` trimmed ('' when none); `.section-tag` exists only when the tag is non-null.
- Row texts: `.scan-started` reads "Completed · started HH:mm" (whitespace-normalized); `.scan-finished` "finished HH:mm"; `.scan-duration` "took <duration>"; the collapsed row has no `button` element; an expanded CANCELLED/FAILED row has none either.
- CANCELLING: the percentage stays at the value shown before it even when the progress grows; the test does not pin the value after CANCELLED, only the "when stopped" caption.
- A CANCELLED/FAILED scan with `phase: null` is not pinned (the specs always give a phase).
- AC-15 test: it concatenates every `<style>` in `document` (comments removed) and needs the component's CSS to contain, outside the media block, a `@keyframes` and an `animation:`/`animation-name:` declaration with a value other than `none`, and, inside `@media (prefers-reduced-motion: reduce) { ... }`, only `animation: none` / `animation-name: none` (no other animation value). Put the stripes' animation declarations outside the block and `animation: none` inside it.
- Local-time ISO strings (no `Z`) in the AC-12 test make "HH:mm" independent of the machine's time zone.
