# ADV-002: Use the collaboration plugin for bounded advisory consultations

- Revision: 1
- Published: 2026-11-01
- Recipient: Claude coordinator/product session
- Requested action: Evaluate compatibility and propose necessary integration changes; do not implement yet
- Scope: Consultation transport, advisor context, and durable result capture
- Supersedes: None; complements ADV-001-r1 discovery
- Evidence: installed agent-collaboration 0.1.0, commit 2b9bbaba22c90c5a1cfff53455534a6e72aab8e1

## Verified behavior

The installed plugin has codex-consult (one exchange) and codex-collaborate
(default five rounds). Both invoke npx -y @openai/codex exec on a handoff file.
They start a new CLI agent, not the advisor's current conversation. This plugin
has no inbox-discovery hook; it does not replace ADV-001.

The marketplace and cached codex-consult skill files have matching SHA-256 hashes.
Installed Codex exec help supports read-only sandboxing, explicit working directory,
and output-last-message. No model invocation was performed in this inspection.

## Recommended use

Default to codex-consult for a concrete unresolved question or a consequential
plan review. Include advisory/CONSULT-CONTEXT.md, the exact proposed change,
constraints, evidence paths, and a precise question. Do not attach full session
history or routinely consult for every ticket/status update.

The CLI reviewer should return text under a read-only sandbox. Claude captures
that output at a known path, then records accepted/rejected findings and evidence
references in its coordinator response or ticket. Preserve useful results under
advisory/; transient tmp output alone is not the durable record. Fresh CLI agents
must not independently allocate ADV IDs or write advisor-owned files.

This explicitly requested consultation capability can use fresh CLI sessions when
invoked by the coordinator, but it does not authorize background polling or
additional automatic implementation sessions. Standing implementation approval
rules remain unchanged. Five-round co-production is not the default coaching mode.

## Compatibility findings to resolve

1. The skill uses gtimeout or a Perl fallback and Bash stdin redirection. Native
   PowerShell lacks those shell semantics. Git for Windows has Perl and GNU
   timeout on this machine, so verify the actual Claude Bash environment before
   declaring a blocker. Windows system32 timeout.exe is a different utility.
2. Prefer the already-installed codex executable or a pinned CLI version over
   an unpinned npx download for repeatable, lower-overhead consultation. Confirm
   Claude's shell can resolve it; this inspection only confirmed PowerShell.
3. Specify read-only sandboxing, repository root, and deterministic final-output
   capture. The current skill otherwise searches for an output file or uses
   terminal text. Handle failure/timeout as no review, never as approval.
4. The project .gitignore currently does not ignore the plugin's tmp directory.
   Propose a narrow ignore for its two transient subdirectories, or an agreed
   adapter location. Do not broadly hide unrelated files.
5. The skill calls two minutes without output a hang. Treat a deadline as a budget
   timeout; it does not prove a hang. Stop only the process launched for that
   consultation, and avoid automatically paying for the same failed call twice.
6. Timestamp/topic paths can collide within a minute. Use a request identifier or
   collision check if multiple consultations are possible.

## Acceptance criteria

- A bounded smoke consultation reads the context and named evidence, returns a
  captured response, and makes no repository edits.
- No active Claude/Gradle process is interrupted.
- Failure is distinguishable from a completed review.
- Final evidence and Claude's disposition survive deletion of transient output.
- No claims of contacting the existing advisor conversation or inheriting its memory.
- Existing ticket and user approval gates remain authoritative.
